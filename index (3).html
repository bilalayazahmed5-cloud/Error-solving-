A small tool.
A useful workflow.

Icarus Verilog (often invoked as iverilog) is a free, open-source Verilog simulation tool. It helps compile HDL source and testbenches, then run simulations to inspect behavior.

01 / The tool

What is Icarus Verilog?

For a student lab, it is a straightforward way to check HDL syntax, build a simulation, and inspect how a design behaves with a testbench.

  • Compile modules and testbenches
  • Catch syntax and elaboration issues
  • Simulate combinational and sequential logic
  • Explore outputs with a waveform viewer
The two-step loop

Compile first. Run second.

01 Compile

Build a simulation image.

iverilog -o sim.out design.v tb.v
→
02 Run

Execute the image with VVP.

vvp sim.out
A good first habit / One message, one question.

When compilation fails, locate the earliest diagnostic and the source line it points to. Check that line and a few lines above it—syntax errors often surface just after the actual typo.

REFERENCE / DIAGNOSTICS

Error explorer.

Six familiar failure modes, unpacked into cause, symptom, and a cleaner version. Search by phrase or filter by where it tends to happen.

E—01 / Syntax↘

Syntax error

The parser reached a token that does not fit the grammar at that point.

Why it happens

A missing semicolon, misspelled keyword, unbalanced delimiter, or malformed expression. The reported line can be just after the typo.

How to fix it

Check the indicated line and the line above it. Balance () and begin/end, then inspect punctuation and spelling.

Faulty
gate.v 
module gate(input a, b, output y)
  assign y = a & b;
endmodule
Corrected
gate.v 
module gate(input a, b, output y);
  assign y = a & b;
endmodule
E—02 / Syntax↘

Missing endmodule

The module never reaches its closing keyword before the file ends or another module begins.

Why it happens

A module declaration was opened but its closing endmodule was omitted, or nested blocks confused the author.

How to fix it

Match each module with one endmodule. Remember that end closes a procedural block, not a module.

Faulty
inverter.v 
module inverter(input a, output y);
  assign y = ~a;
// module is still open
Corrected
inverter.v 
module inverter(input a, output y);
  assign y = ~a;
endmodule
E—03 / Declaration↘

Undeclared signal

A name is used in an expression but is not declared in the module scope.

Why it happens

Typo in a signal name, omitted declaration, or a port name that does not match the module header.

How to fix it

Compare spelling character by character. Declare internal signals as wire or reg as appropriate, or correct the port name.

Faulty
gate.v 
module gate(input a, b, output y);
  assign y = a & b;
endmodule
// elsewhere: assign z = y ^ c;
Corrected example
gate.v 
module gate(input a, b, output y);
  wire c, z;
  assign y = a & b;
  assign z = y ^ c;
endmodule
E—04 / Connections↘

Incorrect port connection

A module instance refers to a port that does not exist, or connects signals in the wrong order.

Why it happens

Port spelling changed, named-port syntax is malformed, or positional arguments do not follow the declaration order.

How to fix it

Check the module header and instance together. Prefer named connections: they make intent visible and tolerate port reordering.

Faulty
top.v 
module gate(input a, b, output y);
  assign y = a & b;
endmodule
gate u1 (.a(x), .bi(z), .y(out));
Corrected
top.v 
gate u1 (.a(x), .b(z), .y(out));
E—05 / Width↘

Width mismatch

Connected vectors have different widths; extra bits may be padded or truncated.

Why it happens

For example, a 4-bit bus is connected to a 1-bit port. This may be a warning rather than a hard compile error, but behavior can be unintended.

How to fix it

Make widths agree explicitly. Slice a bus or widen the destination deliberately; do not ignore the warning.

Faulty
top.v 
module bit_in(input wire a);
endmodule
wire [3:0] bus;
bit_in u1 (.a(bus));
Corrected
top.v 
module bit_in(input wire a);
endmodule
wire [3:0] bus;
bit_in u1 (.a(bus[0]));
E—06 / Testbench↘

Testbench issues

The design may compile, but the testbench provides no useful stimulus or never ends.

Why it happens

Inputs were never initialized, no transitions were applied, clock timing is absent, or the simulation lacks a finish condition.

How to fix it

Initialize every input, apply test vectors, allow time to settle, and finish. Add waveform dumping when you need to inspect signals.

Faulty
tb.v 
module tb;
  reg a, b;
  wire y;
  gate dut(a, b, y);
endmodule
Corrected
tb.v 
module tb;
  reg a, b;
  wire y;
  gate dut(a, b, y);
  initial begin
    a=0; b=0; #10 a=1; #10 b=1;
    #10 $finish;
  end
endmodule

REFERENCE / TERMINAL

Command guide.

Icarus Verilog separates compilation from execution. These commands assume the source files are in your current working directory.

01 / Build an image

Compile with iverilog

Pass the design and testbench source files. The -o option names the generated simulation image.

TERMINAL 
iverilog -o sim.out design.v tb.v

INPUT design.v, tb.v → OUTPUT sim.out

02 / Execute the image

Run with vvp

VVP is the runtime engine for the simulation image created by the compiler.

TERMINAL 
vvp sim.out

INPUT sim.out → RESULT testbench output

Useful flags

Small options, big clarity.

-o
iverilog -o sim.out design.v tb.v
Choose the output image filename.

-g2012
iverilog -g2012 -o sim.out design.v tb.v
Enable SystemVerilog 2012 language features.

-s
iverilog -s tb -o sim.out design.v tb.v
Set the simulation top-level module explicitly.

-Wall
iverilog -Wall -o sim.out design.v tb.v
Enable additional warnings to help spot suspicious code.

When something fails

Read the first compiler message, confirm the filename and line number, and check whether every required module file is included in the compile command.
